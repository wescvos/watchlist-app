# Chat and Sending Movies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let Watchlist users send a movie to one or more friends from any title page and talk about it in Instagram-style one-on-one chats that update every few seconds while open.

**Architecture:** Four new Prisma models (`Conversation`, `Message`, `Reaction`, plus read-state columns on `Conversation`) behind a small server library in `src/lib/chat/`, exposed through user-scoped route handlers under `/api/chat/`. The client polls those routes with one visibility-aware hook; the home header gets a client-only chat icon so `/` stays static.

**Tech Stack:** Next.js 16.2 (App Router), React 19.2, Prisma 7 + Neon Postgres, Auth.js v5 (`getCurrentUserId`/`requireUserId`), Tailwind 4, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-30-chat-design.md`

## Global Constraints

- Authorization per AGENTS.md "Auth": every route/page resolves the user with `getCurrentUserId()` (routes, 401 `{ error: "Unauthorized" }`) or `requireUserId()` (pages), and a conversation or message the user is not a member of is **404, never 403**.
- "On the app" = has a `User` row AND `isAllowedEmail(user.email)`. The people list exposes only `{ id, firstName, image }`, never emails.
- `firstName` = first whitespace-separated word of `User.name`, else the email's local part.
- Message text: trimmed, 1 to **2000** characters, plain text only (React escaping, no HTML, no link previews).
- One conversation per pair: `userAId < userBId` (string compare), `@@unique([userAId, userBId])`.
- Hearts are quiet: they never change `lastMessageAt`, the list preview, or unread state.
- Rating on a card = the sender's `ListEntry.myRating` for that title **at send time** (snapshot column), or none.
- A movie sent with text = two messages: card first, then the text, with the text's `createdAt` 1 ms after the card's.
- Polling intervals: open chat **3000 ms**, chats list **10000 ms**, header badge **30000 ms**; all pause while `document.visibilityState !== "visible"` and fire immediately on becoming visible again.
- Home `/` must stay static (`○` in `next build` output); no `auth()`/`cookies()` in the root layout; the header must fit on one line at 375px.
- Migrations are additive only, generated with `prisma migrate diff --from-schema <HEAD copy> --to-schema prisma/schema.prisma --script`; never `migrate dev`, never run against the DB locally (`.env` is production).
- Never em dashes in code comments or copy. `git add` explicit paths only. Work on local branch `chat`; nothing is pushed before Task 10.

## Review Focus

1. **Blank or oversized text** (`"   "`, 2001 chars). Expected: 400, nothing stored, input keeps the text. Tests in Tasks 4 and 5.
2. **Send to an invalid recipient set** (includes self, an unknown id, or a removed friend; empty list). Expected: 400 and **nothing** created for any recipient, not a partial send. Test in Task 4.
3. **App goes to the background mid-chat.** Expected: no polling requests while hidden; one immediate refresh on return. Test in Task 6.
4. **Long chat** (more than 50 messages). Expected: newest 50 shown; "Load earlier" adds older ones with no duplicates or gaps, and later polls don't drop them. Tests in Tasks 4 and 9.
5. **Writing to a removed friend.** Expected: the chat stays readable, the input is replaced by "This person is no longer on Watchlist.", and the API rejects sends with 400. Tests in Tasks 4 and 9.

### Task 4: Messages

**Files:**
- Create: `src/lib/chat/messages.ts`
- Test: `src/lib/chat/__tests__/messages.test.ts`

**Interfaces:**
- Consumes: Tasks 2 and 3; `ensureCatalogTitle`.
- Produces:
  - `MAX_MESSAGE_LENGTH = 2000`, `PAGE_SIZE = 50`
  - `class ChatInputError extends Error` (routes map it to 400 with its message)
  - `type ChatTitle = { id: string; tmdbId: number; mediaType: MediaType; title: string; year: number | null; posterUrl: string | null }`
  - `type ChatMessage = { id: string; senderId: string; createdAt: string; text: string | null; title: ChatTitle | null; senderRating: number | null; viewerStatus: "WANT" | "WATCHED" | null; heartedBy: string[] }`
  - `type ChatPage = { messages: ChatMessage[]; hasEarlier: boolean; otherLastReadAt: string | null }`
  - `getMessages(userId: string, conversationId: string, before?: string): Promise<ChatPage | null>` (null when not a member; newest `PAGE_SIZE` messages, or the `PAGE_SIZE` before message id `before`; returned oldest-first, ordered by `createdAt` then `id`)
  - `sendText(userId: string, conversationId: string, text: string): Promise<ChatMessage | null>` (null when not a member)
  - `sendTitle(userId: string, input: { recipientIds: string[]; tmdbId: number; mediaType: MediaKind; text?: string }): Promise<{ conversationIds: string[] }>`
  - `toggleHeart(userId: string, messageId: string): Promise<{ hearted: boolean } | null>` (null when the message is not in a conversation of mine)
- Rules: `viewerStatus` is the viewer's own `ListEntry.status` for the card's title. Sending updates `lastMessageAt` but never a reader's lastReadAt; it does mark the sender's own side read. `toggleHeart` never touches `lastMessageAt`.

With no rating, `senderRating` is null. Calls `ensureCatalogTitle` and creates no `ListEntry`.
  - `getMessages` for a non-member returns null; with 51 stored messages returns 50 with `hasEarlier: true`; with `before` = the oldest returned id, returns the remaining 1 with `hasEarlier: false` (Review Focus 4). Ties on `createdAt` order by `id`.
  - `toggleHeart` creates then deletes on two calls; returns null for a message in someone else's conversation; never updates `lastMessageAt`.
