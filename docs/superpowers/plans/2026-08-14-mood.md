# Mood Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each task is implemented and verified on its own; do NOT one-shot the feature.

**Goal:** Replace the "For You" recommendations feature with a "Mood" screen. Twelve moods are pre-tagged onto titles by Gemini and stored on `Title.moods`; browsing a mood is a plain database filter over the Want list, so it is instant, free, and has no rate-limit exposure at browse time.

**Architecture:** A shared `src/lib/gemini/client.ts` (extracted from the recommend provider before that code is deleted) owns the endpoint, JSON mode, timeout, typed errors, and guarded parsing. A `src/lib/mood/` service builds prompts, batches titles at 20 per call, validates responses against the twelve canonical labels, and writes `moods` + `moodsTaggedAt`. Tagging is triggered on add and on refresh (only when untagged) via `after()` from `next/server`, plus a one-off backfill script. Both `/mood` screens are server components querying Postgres directly.

**Tech Stack:** Existing (Next.js App Router 16.2.10 + TypeScript, Tailwind, Prisma 7, Neon Postgres, Vitest, Vercel) plus the already-configured Gemini key. **No new dependency, no new environment variable.**

See the companion spec: `docs/superpowers/specs/2026-08-14-mood-design.md`.

- [x] **Step 2: Write failing tests**

Create `src/lib/mood/__tests__/tagger.test.ts`:

*Prompt:*
- Contains all twelve labels and the Conceptual operative test.
- Contains the dread-vs-Edge-of-seat "PREFER ONE" rule, the dread-vs-Scary rule, and the Edge-of-seat-vs-Big & thrilling rule, and no longer mentions the retired "Tense & gripping".
- Contains the Thoughtful and Weird disambiguation ("Palm Springs is Conceptual but not Thoughtful", "Arrival is Conceptual but not Weird") and the multi-tag worked examples.
- **Privacy:** given a title row that also has `myRating`, `note`, `pinned`, and `watchedAt` populated, the prompt contains the title and its overview but **none** of those values. Assert on the actual rating/note strings being absent.
- Overviews longer than 400 characters are truncated at a word boundary; shorter ones are untouched; a null overview is handled.

*Batching:*
- 45 titles produce 3 calls of 20, 20, 5.
- 20 titles produce exactly 1 call.
- A batch's `index` values are 0-based within that batch.

*Validation (`parseMoodTaggings`):*
- A well-formed response maps to `MoodTagging[]` with only canonical labels.
- An entry with an out-of-range `index` is dropped, the rest are kept.
- An entry whose echoed `title` does not match the batch entry at that index is dropped (misalignment must never write moods onto the wrong film).
- An unknown mood string is dropped individually; the entry survives with its remaining valid moods.
- Duplicate moods collapse.
- An entry with zero valid moods yields an **empty** `moods` array (a legitimate tagging), not a dropped entry.
- Titles absent from the response are simply not returned, so they stay untagged.
- Non-array JSON throws; a malformed entry inside a valid array does not.

*Writes:*
- A successful tagging writes `moods` and sets `moodsTaggedAt`.
- A title matching no mood still sets `moodsTaggedAt` (so it is never retried).
- A batch that throws `GeminiError` leaves that batch's titles untouched, is counted as failed, and does **not** abort the remaining batches.
- `tagIfUntagged` on a row with `moodsTaggedAt` set makes **no** Gemini call.
- `tagIfUntagged` swallows a `GeminiError` (does not reject) so an `after()` callback cannot produce an unhandled rejection.

## Task 7: Full re-tag after the mood-set change (TOMORROW, needs a fresh quota)

The "Tense & gripping" split (spec section 5.0) changed the vocabulary, so the
stored tags no longer match the mood set. **Nothing here may run today:** 15 of
20 requests are spent on `gemini-3.5-flash` and 17 of 20 on `gemini-3.7-flash`.

**Files:** none. This is an operational task.

- [ ] **Step 1: Understand why this is a FULL re-tag, not a partial one**

The obvious shortcut is to re-tag only the 165 titles that carried "Tense &
gripping". That is wrong. Every title was judged against the **whole**
vocabulary, so the other 162 were never offered "Slow-burn dread" or
"Edge-of-seat" and were classified as if those moods did not exist. A partial
re-tag would leave two populations in one library, judged against different
option sets, and no way to tell them apart afterwards. So: all 327 Want titles.

- [ ] **Step 2: Clear the old tags on a fresh daily quota**

Confirm at aistudio.google.com/rate-limit that the target model's RPD is at or
near zero. Then:

```bash
npx tsx scripts/clear-want-moods.ts             # dry by default: reports, changes nothing
npx tsx scripts/clear-want-moods.ts --confirm
```

`scripts/clear-want-moods.ts` clears **both** `moods` and `moodsTaggedAt`, and
only those two columns, so ratings, notes, pinned state and watch dates are
untouched by construction rather than by convention. It refuses without
`--confirm` and prints the current vocabulary plus the counts it would affect,
which also serves as a check that the code really is on the new mood set before
any quota is spent.

Clearing the array as well as the timestamp keeps the intermediate state honest:
327 untagged, every count zero. (The screens are safe either way, since the
picker only counts labels present in `MOODS`, so a retired label is invisible
rather than broken.)

- [ ] **Step 3: Re-run the backfill**

```bash
npx tsx scripts/tag-all-moods.ts --dry-run --model gemini-3.5-flash   # confirm 327 titles, 17 requests
npx tsx scripts/tag-all-moods.ts --model gemini-3.5-flash
```

`gemini-3.5-flash` is the known-good choice: it served the last backfill with 0
failures on a verified request shape. Expect **17 requests** for 327 titles, 3
spare, and ~11 minutes at 15s pacing. The mood screens are live throughout and
will show an emptying then refilling library; that is cosmetic and expected.

- [ ] **Step 4: Re-audit, with the split as the whole point**

Re-run the distribution audit. The success criterion is **not** that the two new
moods sum to the old 165, and it should not be read that way: the whole
vocabulary shifted, so every title was re-judged. What to check:

- **Neither new mood dominates.** If either comes back near 165, the split failed and the definitions need sharpening rather than the tagger blaming.
- **The overlap is small.** Titles carrying *both* Slow-burn dread and Edge-of-seat should be a clear minority. A large overlap means the "PREFER ONE" instruction is not landing, which is the specific failure this split can suffer.
- **Dread appears without Scary.** Michael Clayton, First Reformed and Zodiac-style entries should carry dread and no Scary, proving that rule landed.
- **Edge-of-seat appears without Big & thrilling**, proving the scale rule landed.
- Re-check Conceptual (it was 39, 12%, and correct) for drift, since the whole vocabulary moved underneath it.

- [ ] **Step 5: Report and decide**

If the split worked, nothing more to do. If either mood is still oversized or
the overlap is large, the fix is the definitions in `src/lib/moods.ts` plus
another full re-tag on another day's quota, **not** a patch to the screens.
